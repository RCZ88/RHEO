- [2026-09-30] ELECTRON HAS NO NATIVE FIND BAR — a keydown handler whose body is "let the browser handle Ctrl+F natively" is a silent feature-killer: in Electron that comment means the key does NOTHING. The real culprit was `NativeFindOverlay.tsx`, which full-screened `rgba(0,0,0,0.55)` + `backdropFilter: blur(6px)` (a curtain, not a lens) and merely LISTED matching text nodes without highlighting or scrolling. A working find bar = small fixed bar + `mark` elements injected by a TreeWalker (collect all matching text nodes FIRST, then mutate — the walker cannot survive its own surgery) + fully reversible teardown (`parent.normalize()`). **SECOND LESSON, cost a cycle:** when a MutationObserver rebuilds a derived DOM set, drive re-application of the ACTIVE item off a monotonic `version` counter, NOT off `setCount(n)` — React bails out of a setState with an unchanged value, so the active/highlight attribute silently vanished whenever the count stayed the same.
- [2026-09-30] THE COORDINATION TOOL WAS SILENTLY DEAD ON LINUX. `agent-coordination/coord.mjs` ended with `if (import.meta.url === \`file://${process.argv[1]}\`) main()`. `process.argv[1]` is RELATIVE (`agent/docs/.../coord.mjs`), so the guard compared `file:///run/media/.../coord.mjs` against `file://agent/docs/...` — never equal, `main()` never ran, and EVERY CLI command (`register`/`claim`/`status`/wrappers) returned `EXIT=0` with empty stdout and no registry write. **KEY LESSON: exit code 0 plus no output is NOT evidence a tool ran — and a coordination layer that no-ops defeats the entire purpose of having locks.** Fixed with `pathToFileURL(process.argv[1]).href === import.meta.url` (the plain template also breaks on any path containing a SPACE, which this repo's "App Tracker" path does). The library imports (`run-exclusive.mjs`, `db-guard.mjs`) were unaffected, so build/app/db locks WERE enforced — only the CLI was dead. Always `coord.mjs status` and confirm it prints `AGENTS (n)`, not just check `$?`.

- [2026-09-30] THIS MACHINE IS SHARED AND BUILDS ARE OOM-KILLED, NOT CODE-ERRORS. Symptom: `node scripts/build.mjs` dies right after `transforming...` with NO error text, log ends in d3 `CIRCULAR DEPENDENCY` warnings, and `strings build.log | grep ERROR` finds nothing. That is the OOM killer, not a bad edit. **CRITICAL ON A SHARED MACHINE: do NOT pass `--forbid app`** — with ~10 concurrent agents somebody is always running the app, so `run-exclusive.mjs build --forbid app` refuses nearly every time and the repo becomes unbuildable. Take the BUILD lock alone (that is the only thing preventing two builds from corrupting `dist/`) and run `run-exclusive.mjs build -- node scripts/build.mjs` with no `--forbid`; an already-open window holds its renderer in memory so a `dist/` swap cannot corrupt it. The only cost is that `dist/` can vanish mid-load and you get the "RHEO failed to start / please rebuild" fallback — recoverable by relaunching, not data loss. — check `free -m` (swap pegged at 100%, available dropping under 1GB) and `pgrep -f vite` (other agents run `npm run build` with `NODE_OPTIONS=--max-old-space-size=8192`, i.e. an 8GB heap request). **How to tell a real error from OOM:** a genuine break names a file and line (`src/pages/X.tsx:3123 ERROR: Unexpected closing "span"`); an OOM kill names nothing. **How to tell whose break it is:** `git status --porcelain <file>` — `MM` means another agent is mid-edit, and the fix is to WAIT for them to finish, never to edit their file. **How to verify your own work while blocked:** `npx esbuild <file> --outfile=/dev/null --loader:.tsx=tsx --jsx=automatic` per file (writes nothing to dist/, no lock needed) plus a `tsc` grep scoped to your own paths — the repo has ~7,297 pre-existing tsc errors so a bare `tsc` exit code is meaningless.

- [2026-10-01] A `vite build` THAT DIES SILENTLY AFTER `transforming...` IS NOT A CODE ERROR — on this box it is almost always the OOM killer, and it leaves TWO traps behind. (1) **`dist/` gets WIPED mid-build**: `emptyOutDir` clears it, the build dies before writing, and you are left with no `index.html` and 0 assets = instant black screen on any reload. Always re-verify `ls dist/index.html` + `ls dist/assets | wc -l` after a build, never trust the exit code or a `Build complete!` you did not see in the output. (2) **The coordination lock survives the dead process**: `ttlMs` is 1,200,000 (20 MINUTES), and `coord.mjs status` still lists the killed build as a live agent, so a stale lock is indistinguishable from a real one. `ps -p <pid>` decides it. Also: `npm run build` hardcodes `NODE_OPTIONS=--max-old-space-size=8192` — lowering it to 3072 does NOT help when 10 opencode agents are competing; the contention is the cause, not the heap. **And do not leave build agents registered after they get REFUSED on the lock — each one pollutes `status` and hides the real holder.** **VERIFY WITHOUT RISKING `dist/`:** `emptyOutDir` wipes it BEFORE writing, so build to a scratch dir instead (`vite build --outDir /tmp/... --emptyOutDir`) — compilation + the whole rollup graph get verified and `dist/` is never at risk. **AND `pgrep -c -f 'vite build'` false-positives on the polling shell whose own command line contains that string** (it said 2 while `ps` showed NONE); confirm with `ps -eo pid,etimes,rss,args | grep -E "[v]ite"` before deciding you cannot get a slot.
