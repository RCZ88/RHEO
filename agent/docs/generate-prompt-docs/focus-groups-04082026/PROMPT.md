## Engineering / Data Layer

The **core insight** the receiving AI must exploit: `focus:start` ALREADY accepts
`cfg.allowed: { apps, domains, tiers }` and persists it to `deep_focus_sessions.allowed_json`.
Focus Groups therefore needs NO change to the enforcement engine — only:
(a) a persistent store of named groups, (b) a UI to manage them, (c) plumbing to pass a
group's `allowed` into `focus:start`, (d) linking the session to progress toward daily goals.

### Existing fact table for goal progress attribution
`useGoalProgress.ts` aggregates `logs` rows by lowercased `category` → seconds, matched against
`goal.target.matchCategory`. **Therefore a focus session "counts toward a goal" only if the
apps/websites the user actually used during the session are logged to `logs` with a `category`
equal to the goal's `matchCategory`.**

### Required additions

#### A. Storage: `src/domains/focus/focusGroupManager.ts` + `focusGroupSchema.ts`
- Add table `focus_groups`:
  `id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT UNIQUE, allowed_json TEXT NOT NULL,
   category TEXT, created_at TEXT DEFAULT (datetime('now','localtime'))`
  where `allowed_json` is `JSON.stringify({ apps:[...], domains:[...], tiers:[...] })`.
  (Mirrors the exact `allowed` shape already used by `focus:start`.)
- Add table `focus_group_usage`:
  `id INTEGER PRIMARY KEY AUTOINCREMENT, focus_group_id INTEGER REFERENCES focus_groups(id)
   ON DELETE CASCADE, session_id INTEGER REFERENCES deep_focus_sessions(id) ON DELETE CASCADE,
   goal_id TEXT, used_at TEXT DEFAULT (datetime('now','localtime'))` — links a focus session
  (and the goals its category matched) to a group, for the "show that you did a session for
  that thing" requirement.
- Service class `FocusGroupManager` (mirror `GoalStore` localStorage + DB dual pattern):
  `list(): FocusGroup[]`, `get(id): FocusGroup|null`, `save(group): FocusGroup`,
  `remove(id): void`, `link(sessionId, groupId, goalIds: string[]): void`.
  Storage: persist to DB via a new IPC `focus-group:*` (below) AND cache in
  `localStorage` under `df_focus_groups` for offline.
- `FocusGroup` type:
  `{ id: string; name: string; allowed: { apps: string[]; domains: string[]; tiers: Tier[] }; category: GoalCategory|null; createdAt: string }`

#### B. Preload + main IPC (do NOT break existing calls)
Add to `deskflowAPI` in `src/preload.ts` and `ipcMain.handle` in `main.ts`:
```typescript
focusGroup: {
  list: () => ipcRenderer.invoke('focus-group:list'),
  save: (group: { name: string; allowed: object; category?: string }) =>
    ipcRenderer.invoke('focus-group:save', group),
  remove: (id: string | number) => ipcRenderer.invoke('focus-group:remove', id),
  startWith: (groupId: string | number, durationSec: number, strictness: Strictness) =>
    ipcRenderer.invoke('focus-group:start-with', groupId, durationSec, strictness),
},
```
`focus-group:start-with` reads the group's `allowed_json`, then calls
`focusManager.start({ durationSec, strictness, allowed })` and records the linkage into
`focus_group_usage` (so we can later report "you spent X minutes on Development").
Return the `FocusPublicState` (and ideally also the `allowed`/category so the renderer can
credit goals — see data-flow note below).

#### C. Progress-attribution data flow (FIX the broken `useFocusGoals`)
`useFocusGoals.ts` is currently broken (reads fields not present in `getPublicState`). The
receiving AI must fix attribution. Preferred minimal approach that stays within existing
infra:
- When `focus:start` is called FOR a group, also stash `{ groupId, categories:
  [g.category].filter(Boolean) }` in a renderer-side singleton (`useFocusActiveGroup`).
- `useFocusGoals` reads that singleton (NOT `state.allowed_json` — which doesn't exist) to know
  which goals match the current session, and ticks `GoalStore.accumulateProgress` per second.
- On `focus:ended` / state→inactive, call `GoalStore.applyAccumulated` + `saveGoal` to persist.
- Keep `useGoalProgress.ts` (DB/category based) as the source of truth for the DailyPlannerCard
  list; the live accumulated seconds are a transient overlay.

This deliberately AVOIDS modifying `focusManager.ts`'s `getPublicState()` shape (which would
risk breaking QuickFocusCard/useDeepFocus); attribution is handled on the renderer side from
the group the user selected.

### D. Hook layer (new)
- `src/hooks/useFocusGroups.ts`: load/save/remove groups via `deskflowAPI.focusGroup.*`;
  exposes `{groups, loading, saveGroup, removeGroup, selectedId, setSelectedId}`.
  Cache in `localStorage` + optimistic update.
- `src/hooks/useDragDuration.ts`: drag-handle on a 0–180 min range; returns
  `{minutes, setMinutes, dragState}` and a `DragDurationBar` presenter. Mirrors the existing
  preset-chip UX but lets the user drag; minimum `1` min, snap to 5-min, live label.

### E. UI components (new, in `src/components/focus/`)

   FAB. Selected group chip shows name + category dot; clicking opens `FocusGroupEditor`.
   On select, calls `focusGroup.startWith(id, duration, strictness)` then `start()`-style flow.
   Empty state: "Create a focus group (e.g. Development) to pre-set allowed apps."
2. `FocusGroupEditor.tsx` — modal drawer (shadcn `sheet` + `input`/`select`/`scroll-area`),
   two panes: **Apps** (multiselect from detected running apps) + **Websites** (chips input).
   Presets: "Development" (VS Code, PyCharm), "Video Creation" (CapCut, OBS, …). Tiers

3. `DragDurationBar.tsx` — horizontal slider (shadcn `slider`) 5…180 min, thumb label follows

## UX task (human-centred — the receiving AI designs the looks)

- **Group list** in FocusSection: horizontal scrollable chip row. Each chip: left-border
  accent = the group's category color (work=cyan `#22d3ee`, learning=purple `#a78bfa`,
  health=red `#f87171`, personal=green `#4ade80`), group name, a small count of
  apps/domains. Selected = filled `--dk-accent` background; hover = `border-white/20`.
  Empty → ghost "＋ New group" chip that opens the editor.
- **Group editor** (drawer, right-side, shadcn `sheet`): header "Edit group" / "New group",
  input field for name, section "Allowed apps" (multiselect list with running-app detection
  + colour chip), "Allowed websites" (input chips), "Protection tier" (multiselect tags
  `productive/neutral/non_allowed`-ish). CTA "Save group" disabled until name+≥1 rule.
- **Drag duration**: a 5…180 min slider, thumb is a small circular number ticker, track is
  `bg-zinc-800/80` with a cyan fill to the left, current value shown live at the thumb.
  Below: preset chips [15·25·45·90] that snap the slider.
- **Challenge mode** (stopwatch): when engaged, the duration slider hides and a "Stop
  challenge" button appears; the group restriction stays active so the challenge is bounded
  to the group's allowed set — directly satisfying the user's "challenge yourself" request.
- **Live goal credit**: while a grouped session is active, the matching goal's `GoalProgressBar`
  (existing) ticks up second-by-second (via `useFocusGoals` accumulator). Use
  `border-beam` on that goal's card to draw attention while active.
- **End-of-session toast**: on `focus:ended`, a transient snackbar shows:
  "Development · 28 min · 75% of 'Code Project' goal" — linking session→group→goal.
  Use `sonner` (installed shadcn) for the toast.
- **Empty / loading / error**:
  - Loading groups → skeleton chips (shimmer via `dk-skeleton`).
  - No groups → "No focus groups yet — create a group to pre-select apps for your next session."
  - Save failed → inline red banner on the drawer + retry.
- **Accessibility**: `aria-label` on every icon button, `role="group"` for the chip list,
  ESC closes the editor sheet, slider keyboard-accessible (←/→, Home/End).
