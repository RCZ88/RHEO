Moving around

~/handbook/02-navigation

The terminal is always “standing” in exactly one folder. These commands move your feet.

$pwdcore
doesPrint where you are.
whenWhenever you're lost.
$ls -lahcore
doesList files: all (including hidden), long format, human sizes (K/M/G).
noteHidden files start with a dot — configs live there.
$cd Documents · cd .. · cd ~ · cd -core
doesChange folder. .. = parent, ~ = home, - = where you just were.
gotchacd with no argument also goes home.

Paths — the one concept everything builds on

Two ways to point at the same folder:

TypeExampleMeaning
Absolute/home/cleme/photosstarts from / (the root). Works from anywhere.
Relativephotosstarts from where you're standing.

/ is the top of the whole disk tree — there is no “Drive C:”. One tree, everything hangs off /.

rule of thumb
Typing paths by hand invites typos. Type the first letters, hit Tab — the terminal fills the rest, including the trailing /.
03

Files & folders

~/handbook/03-files

Create, copy, move, delete. Copy and move are “safe-ish”; delete is forever.

$mkdir -p projects/c/lesson1core
doesMake a folder. -p creates missing parents too — always use it.
$touch notes.txtcore
doesCreate an empty file, or update its timestamp if it already exists.
$cp -r folder/ backup/core
doesCopy. -r = recursive, needed for folders. No undo, no trash — it overwrites silently.
gotchaA trailing slash on the source (folder/) means contents of the folder; without it, the folder itself. When in doubt, Tab-complete.
$mv old.txt new.txt · mv file.txt ~/Documents/core
doesMove or rename — same command. Also has no undo.
$rm file.txt · rm -r folder/core
doesDelete a file. -r deletes a folder and everything inside.
gotchaThere is no Recycle Bin. rm is permanent the instant you hit Enter.
$ln -s /real/path shortcutpower
doesSymlink — a signpost pointing at another file/folder. Deleting the signpost doesn't delete the target.
safer habit
sudo dnf install trash-cli, then use trash-put file — a real trash can with undo.

Reading & finding

~/handbook/04-reading

Look inside files, and find the needle in a haystack of logs and code.

$cat file.txtcore
doesDump a whole file to the screen. Fine for small files, floods your terminal on big ones.
$less bigfile.logdaily
doesRead a big file page by page.
keysSpace next page · / search · q quit. The pager for anything long.
$head -n 20 file · tail -n 20 file · tail -f filedaily
doesFirst/last lines. tail -f follows the file live — watch a log update in real time. Ctrl+C to stop.
$grep -rni "TODO" ~/projectsdaily
doesSearch text: recursive, case-insensitive, line numbers. The single most useful search tool that exists.
when“Where did I write that?” → grep -rn "int main" .
$find ~ -name "*.c" -mtime -7power
doesFind files by name, type, date, size. -mtime -7 = changed in the last 7 days.
gotchaUnrestricted find / on huge disks spews forever. Always scope the path and add -maxdepth 2 when you can.
$which gcc · whereis gccdaily
doesWhich program actually runs when you type a name.
whenFirst check on “command not found” or “wrong version”.
$wc -l file · sort file | uniq -cpower
doesCount lines. Sort + count duplicates — the classic log-analysis combo.
grep vs find, one line
grep searches inside files (by content). find searches for files (by name/properties).
05

Permissions & sudo

~/handbook/05-permissions

Every file has an owner and three permission slots. “Permission denied” stops being scary once you can read this line:

-rwxr-xr--  cleme  cleme   4096  notes.txt
SlotLettersNumbersMeans
owner (you)rwx7read, write, execute
groupr-x5read + execute
everyoner--4read only

Numbers: r=4, w=2, x=1, added per slot. 755 = you can do everything, others read+run.

$chmod +x script.sh · chmod 755 script.shdaily
doesChange permissions. +x = make executable — required before ./script.sh will run.
#sudo <command>sudocore
doesRun one command as admin. Asks for your password, remembers it for a few minutes.
gotchaOnly sudo for system-wide things — /etc, /usr, drivers, system services. Your own files and desktop settings never need it.
$whoami · idcore
doesConfirm which user you are. Surprisingly useful when “permission denied” makes no sense.

System health

~/handbook/09-health

“Why is my laptop slow / full / hot?” Answer it in four commands.

$df -hdaily
doesFree space per filesystem. / filling up = system problems.
noteShows space inside partitions, not unallocated disk space (§17).
$du -xhd1 ~/ 2>/dev/null | sort -hdaily
doesSizes of folders directly inside ~, biggest last. Re-run inside any big folder to drill down. 2>/dev/null hides “permission denied” noise.
when“What's eating my disk?” — beats any GUI analyzer.
$free -h · top (or htop)daily
doesMemory usage. top = live process table: CPU%, RAM%, who's hogging. q quits; htop is the prettier version.
$pgrep -a firefox · kill 1234 · kill -9 1234daily
doesFind a process by name (with its command line). kill asks it to close — always try this first. kill -9 destroys instantly; only for processes that ignore the polite kill.
$uname -r · uptimecore
doesWhich kernel is running now, and time since boot. (rpm -q kernel-core lists what's installed — a different thing. See §16.)

11

Coding in the terminal

~/handbook/11-coding

No IDE needed. Editor + compiler + runner, all text. Same pattern for every language: write → compile/build → run.

the C toolchain — the full workflow

Every C program lives in .c files. The compiler translates them into an executable binary.

# 1. write the code
nano hello.c

# 2. compile: source file -> executable named "hello"
gcc hello.c -o hello

# 3. run it. The ./ is required (see below)
./hello
why ./hello and not just hello?
The shell only searches the folders in your PATH (system bin folders) — for safety, your current folder is not in it. ./ says “the program right here”.
gcc flagWhy you'd want it
-Wall -Wextraall warnings on — meets the bugs before they bite
-gdebug info, lets gdb show line numbers
-O2optimized build for release
-lmlink the math library (sqrt, pow, …)
$gcc main.c utils.c -o appdaily
doesMultiple source files compile into one program. One -o output, many inputs.
#sudo dnf install gccsudo
fixesgcc: command not found. Fedora ships without a compiler; one install fixes it. Verify with gcc --version.
$gdb ./hello → run → btpower
doesDebugger. Compile with -g first. bt (backtrace) shows exactly which line crashed. q quits.

Once a project outgrows one or two files, typing gcc lines gets old. make reads a recipe (Makefile) and rebuilds only what changed:

# Makefile — note: tabs, not spaces, before gcc
app: main.c utils.c
	gcc -Wall main.c utils.c -o app

# then just:
make
./app
terminal editor as your C IDE
Write in vim or nano, compile with gcc, split the screen with tmux (sudo dnf install tmux) to see code and output side by side. That's the whole “IDE”.

other languages, same pattern

LanguageWriteRun
Pythonnano app.pypython3 app.py
JavaScriptnano app.jsnode app.js
Javanano App.javajavac App.java → java App
Rustnano main.rsrustc main.rs → ./main
C++nano app.cppg++ app.cpp -o app → ./app
$python3 -m venv .venv && source .venv/bin/activatedaily
doesPython project environment — isolates each project's packages. deactivate to leave.
$npm cipower
doesRecreate Node dependencies exactly from the lockfile. Moving projects: copy the source, run npm ci — never copy node_modules.

Services & logs

~/handbook/12-systemd

Modern Linux is run by systemd. Two tools run the show: systemctl controls services, journalctl reads their logs.

the distinction that prevents disasters
systemctl = system-wide services (network, display manager). systemctl --user = your session's services (KDE, apps). Desktop problems are usually user services — no sudo.
CommandDoes
systemctl status <svc>is it running? recent errors? (no sudo needed)
sudo systemctl restart <svc>stop + start it
sudo systemctl enable <svc>start automatically at boot
systemctl --user status <svc>same, but for your session
journalctlReads
journalctl -blogs since this boot
journalctl -b -1previous boot — golden after a crash/forced shutdown
journalctl -b -1 -kprevious boot, kernel messages only
journalctl --user -b -u <svc>one user service, current boot
journalctl -ffollow live, like tail -f
$journalctl -b -1 | grep -Ei "error|fail|suspend"power
doesLogs are huge; grep cuts them to what matters. For graphics/power: grep -Ei "PM:|i915|drm|ACPI".

Clock & time

~/handbook/13-time

A wrong clock breaks logins, TLS certificates and tokens while your timezone looks perfectly fine. One command diagnoses it.

$timedatectl statusrescue
doesEverything at once: system clock, RTC (motherboard clock), timezone, NTP state.
wantSystem clock synchronized: yes and RTC in local TZ: no.
#sudo timedatectl set-ntp true · sudo timedatectl set-local-rtc 0sudorescue
doesTurn on network time sync. Keep the hardware clock in UTC (the Linux standard — prevents dual-boot/timezone drift).
$date +%spower
doesUnix timestamp — handy when debugging “token expired” errors.
gotcha
NTP service: active only means the sync daemon runs — not that it succeeded. The line that matters is System clock synchronized: yes.

When the GUI dies

~/handbook/14-gui-rescue

Black screen, dropped to a TTY (full-screen text login)? Don't reboot yet — the system is fine, the graphical layer just fell over.

$Ctrl + Alt + F3 … back with Ctrl + Alt + F2rescue
doesSwitches between virtual terminals. Your GUI sits on one TTY; F3 gives you a spare one to work from.
gotchaTyping exit in a TTY just logs out of it — it does not bring KDE back.
$loginctl list-sessionsrescue
doesSee your sessions: which TTY, which user, is one graphical?
$systemctl status display-manager --no-pagerrescue
doesChecks the login-screen service without assuming SDDM or GDM. display-manager always points at whichever your system uses.
#sudo systemctl restart display-managersudorescue
doesRestarts the graphical login screen. Kills your current session — save work first.
15

Snap apps & KWallet

~/handbook/15-kwallet

Snap apps are sandboxed, so they ask KDE's KWallet for secrets — and KWallet asks you for its password. Repeatedly.

diagnose the layer, not the app
The chain is app → D-Bus → your session's credential service → KWallet → unlock prompt. The prompt proves the chain reached KWallet — not that the app or Snap is broken.
$kwalletmanager · systemsettingsdaily
doesKDE Wallet Manager (change/remove wallet password) and KDE System Settings (can disable the Wallet subsystem). GUI apps launched from the terminal.
$busctl --user list · pgrep -a spotifypower
doesSee which session services are running on D-Bus, and verify the app process is alive.
no sudo here, ever
KWallet and KDE session services belong to your user. sudo-ing them breaks things and fixes nothing.
16

Black screen after suspend

~/handbook/16-suspend

Suspend involves the kernel, GPU driver, firmware and the desktop. A machine can resume at kernel level while the screen stays black — so read the log before changing anything.

$systemctl suspendrescue
doesControlled suspend test from the terminal. If this works, basic suspend is fine and the problem is intermittent.
$journalctl -b -1 -k | grep -Ei "PM:|i915|drm|ACPI|suspend|resume"rescue
doesThe money command. PM: suspend exit = the kernel woke up; errors after that point = GPU/desktop problem, not suspend itself.
$uname -r vs rpm -q kernel-corepower
doesWhat kernel is running vs installed. Testing a regression: reboot, pick another kernel in GRUB, confirm with uname -r.
$cat /sys/power/mem_sleeppower
doesShows which suspend modes exist; [brackets] mark the active one. No deep listed = only s2idle; don't chase deep-sleep tweaks.
gotchas that waste afternoons
NVIDIA fixes don't apply if Intel drives your screen (check which GPU owns the display first). ACPI errors near suspend = firmware talking, not necessarily the cause. Don't touch GRUB or kernel parameters before the log names the guilty subsystem.

NTFS cleanup & disks

~/handbook/17-disks

Cleaning a Windows partition from Fedora, safely: look → identify → verify → delete the exact target → verify.

$lsblk -o NAME,SIZE,FSTYPE,FSAVAIL,FSUSE%,MOUNTPOINTSdaily
doesMap of all disks and partitions: what's mounted where. Step one before touching any storage.
#sudo parted /dev/nvme0n1 print freepowersudo
doesShows unallocated space between partitions. df free space is inside a filesystem; unallocated space is outside partitions — different things.
$find /run/media/cleme/WinSSD -maxdepth 2 -type d -iname "*pycharm*" -printpower
doesBounded search for a known app on a huge partition. Always scope the path and cap -maxdepth — an unbounded find on a Windows drive floods your terminal.
#ls -lah "/path/you/found" → sudo rm -rf "/exact/dir"sudorescue
doesLook first, delete the exact directory second, verify with ls/du third.
neverBulk-delete Users, Windows, ProgramData, WindowsApps. IDE installs under Program Files are not your projects — projects live under Users. Search for them separately.
#sudo ntfsfix -n /dev/nvme0n1p3rescuesudo
doesRead-only NTFS check (-n = no changes). Diagnosis only — not a repair tool. Never resize a mounted read-write filesystem: sudo umount first.
18

Danger zone

~/handbook/18-danger

Commands that can wreck a system in one keystroke. Know them to avoid them — not to use them.

sudo rm -rf /
rm -rf is irreversible: no trash, no undo, no “are you sure”. A typo in the path has destroyed systems. Mitigation: type the path, Tab-complete it, ls it first — only then prefix with rm -rf.
dd if=... of=/dev/sdX
Writes raw bytes straight to a disk, bypassing every safeguard. One wrong letter in of= = wiped drive. Triple-check with lsblk before even thinking about it.
curl ... | bash
Runs whatever a website hands you, as you. Read the script first, or at least know the source.
the mindset that keeps systems alive
Diagnose the layer before changing it → change one thing → verify → repeat. Read-only commands first (status, ls, journalctl), mutating commands last. sudo is the last resort, not the first tool.
